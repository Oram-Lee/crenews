# S&I CRE 뉴스 큐레이션 — 프로젝트 현황 & 인계 요약

> 새 대화에서 이 문서 + 4개 파일(`collect_news.py`, `app.py`, `index.html`, `weekly.html`)을 함께 올리면 즉시 맥락 파악 후 작업을 이어갈 수 있도록 정리한 문서입니다.

---

## 1. 프로젝트 한 줄 요약

상업용부동산(CRE) 뉴스를 자동 수집·AI 큐레이션해서 **뉴스레터 HTML/엑셀**로 만들어 주는 사내 도구. 마케팅팀이 매일/매주 발송용 콘텐츠를 만드는 데 사용한다. **Daily(일간)** 와 **Weekly(주간)** 두 운영 모드가 있다.

- 배포: 백엔드(`app.py`+`collect_news.py`)는 **Render.com**, 프론트(`index.html`+`weekly.html`)는 **GitHub Pages**. 서비스 주소 예: `crenews.onrender.com`.
- 수집원: **네이버 뉴스 API + 구글 뉴스 RSS**.
- AI: **Claude / Gemini 폴백 체인** (선별·요약·하이라이트 선정에 사용).
- 데이터: 결과는 `data/news.json`(일간), `data/weekly_news.json`(주간), 누적 풀은 `data/weekly_pool.json`.

---

## 2. 아키텍처 & 핵심 메커니즘

```
[프론트]  index.html (Daily SPA)  /  weekly.html (Weekly SPA)
   │  설정값을 localStorage에 저장 → 수집 시 POST 본문에 실어 전송
   ▼
[백엔드]  app.py (Flask)
   │  ① POST 본문의 설정을 data/run_overrides.json 에 기록
   │  ② subprocess 로 collect_news.py 실행 (--mode / --overrides 인자)
   │  ③ 진행상황은 백그라운드 스레드 + /api/job/status 폴링으로 전달
   ▼
[엔진]   collect_news.py
        apply_runtime_overrides(run_overrides.json) → 런타임 설정 주입
        수집 → 필터/중복제거 → (AI 선별+요약) → JSON 산출
```

### ⭐ 오버라이드 통로 (가장 중요 — "재배포 없이 설정 적용")
프론트에서 바꾼 설정(키워드·공신력·프롬프트 지침 등)은 **코드 수정/재배포 없이** 다음 수집부터 바로 적용된다. 경로:
`localStorage → POST 본문 → app.py 가 run_overrides.json 기록 → collect_news.apply_runtime_overrides() 가 읽어 모듈 전역에 주입`.

전달되는 필드(= `getCollectOverrides()`/`getOverrides()` 가 만드는 객체):
| 필드 | 의미 | collect_news.py 반영처 |
|---|---|---|
| `keyword_override` (bool) | 키워드로 검색어 교체 여부 | search/rss 쿼리 교체 |
| `keywords` (dict) | 카테고리별 키워드 | 〃 |
| `source_authority` (dict) | 매체명→공신력 점수 | `SOURCE_AUTHORITY` 보강 |
| `source_domains` (dict) | 도메인→매체명 | `EXTRA_SOURCE_DOMAINS` |
| `prompt_global` (str) | 공통 프롬프트 지침 | `EXTRA_PROMPT_GLOBAL` |
| `prompt_categories` (dict) | 카테고리별 프롬프트 지침 | `EXTRA_PROMPT_CATEGORIES` |
| `enabled_categories` (list) | 활성 카테고리 (weekly) | `ENABLED_CATEGORIES` |

`localStorage` 키는 **index.html ↔ weekly.html 공유**: `cre_keywords`, `cre_keyword_override`, `cre_authority`, `cre_sites`, `cre_prompt_global`, `cre_prompt_cats`, (+weekly 전용) `cre_enabled_categories`.

## 3. 카테고리 (6개, ID 고정)

`real_estate_market`(부동산 시장 & 정책), `office_lease`(오피스 임대차), `asset_transaction`(자산 매입·매각), `corporate_space`(기업 공간 전략), `industrial_asset`(산업용 자산: 물류·DC·공장), `smart_esg`(스마트빌딩 & ESG).

- **Weekly 기본 활성**: ESG 제외한 5개 (`cre_enabled_categories` 기본값). 마케팅팀 Weekly 운영안이 5개 카테고리 기준이기 때문.

## 4. 파일별 상세

### `collect_news.py` (엔진, ~2,950줄)
- **공신력**: `SOURCE_AUTHORITY`(통신사 100 ~ CRE커뮤니티 45 ~ 포털폴백 20) + `_source_authority()`. 중복제거 시 "공신력 높은 매체 보존". `AUTHORITY_RANK_WEIGHT=0.01` 로 선정 정렬에 가산(관련도 지배 유지, 동점/근소차일 때만 공신력 우선).
- **한줄 정리 클램프** `_clamp_insight(text, max_len=30)`: 한줄요약(`short_summary`)·한줄평(`comment`)을 **완결-인지형**으로 정리. 단순 절단이 아니라 끝에 매달린 조사·연결어미(없이/리스크에 등)를 제거해 "잘린 느낌"을 방지. (정상 단어 보호: '주의/정의' 등 어간 2자 미만 보호, '로' 제외로 고속도로 보호.)
- **통합 프롬프트** `_build_combined_prompt()`: 선별+요약을 1회 호출로 처리. **구조는 고정**(기사 주입 `{news_text}`, JSON 스키마, 파싱 규칙), 그 사이 **2지점에 사용자 지침 주입**:
  - 카테고리 정의 바로 뒤 → `EXTRA_PROMPT_CATEGORIES[cat_id]` (선별/제외용, 예: 광고성 기사 제외)
  - 요약 규칙 뒤 → `EXTRA_PROMPT_GLOBAL` (톤/길이/스타일용)
  - 요약 규칙: summary(개조식 ▪ 최대 2줄·각 40자), short_summary(완결 1줄·30자), comment(완결 인사이트·30자·명사 또는 짧은 서술어 마무리, 조사로 끝내지 말 것).
- **하이브리드 Weekly**:
  - 상수: `WEEKLY_POOL_PATH="data/weekly_pool.json"`, `WEEKLY_OUT_PATH="data/weekly_news.json"`, `WEEKLY_PER_CATEGORY_AI_CAP`(카테고리당 AI 투입 상한), `ENABLED_CATEGORIES`.
  - `run_collect_only()` — **매일 호출. 수집+필터까지만, LLM 미사용(사실상 무료)**, 주간 풀에 중복제거하며 누적. (오래된 항목 정리 포함.)
  - `run_weekly()` — **주 1회. 2단 선별**: 풀에서 기간 추출 → `_rule_rank()`(관련도+공신력+최신성, 토큰 0) 로 카테고리당 상위 N만 추림 → `ai_curate()` 로 요약 → `cross_category_dedup()` → `generate_highlights()` → `weekly_news.json` 산출.
  - `generate_highlights()` — 주간 선별 기사 전체에서 "중요도·산업영향도·**S&I 연관성**" 기준 Top-N 선정. S&I 맥락은 `EXTRA_PROMPT_GLOBAL`(없으면 기본 S&I 설명) 사용. Claude→Gemini→룰 폴백.
  - `main()`: `--mode daily|collect|weekly` 디스패치, `--top`(하이라이트 건수), `--from-date/--to-date/--days`, `--overrides`, `--category`.

### `app.py` (Flask, ~560줄)
- 일간: `/api/collect/news`(POST, 수집+큐레이션), `/api/collect/indicators`, `/api/auto-collect/status`.
- 주간: **`/api/weekly/collect`**(POST, 수집전용=매일), **`/api/weekly/curate`**(POST, 큐레이션+하이라이트=주간), **`/api/weekly/pool`**(GET, 풀 현황).
- `_write_run_overrides(body)` 가 위 7개 필드를 `run_overrides.json` 에 기록.
- 진행상황: `/api/job/status?job=...&since=N` → `{job,running,done,success,started,ended,logs:[],total}`. (Render Free 900s 타임아웃 회피용 백그라운드 스레드 + 폴링 구조.)

### `index.html` (Daily SPA, ~5,490줄)
- 일간 뉴스 로드/편집/내보내기(웹 카드, **HTML**, **엑셀** — 엑셀은 웹과 동일한 `ai_comment`/`ai_short_summary` 필드 사용).
- 좌측 설정 모달: 🏷️키워드 관리, ⚖️매체 공신력(티어+사이트 등록), 🔌소스, ✍️큐레이션 프롬프트(공통+카테고리별 탭, 고정구조 미리보기).
- **상단 GNB에 "Weekly News Curation" 버튼** → `weekly.html` 로 이동.

### `weekly.html` (Weekly SPA, ~500줄)  ← 하이브리드 운영 화면
- 헤더: "매일 수집으로 풀을 쌓고, 주 1회 큐레이션 + S&I Weekly Highlights 생성 (하이브리드)".
- 좌측 사이드바(설정 유지): 🗂️활성 카테고리(인라인 모달), ✍️큐레이션 프롬프트(인라인 모달, index.html과 키 공유) / 키워드·공신력·소스는 index.html 새 탭 연동.
- 본문:
  - **① 매일 수집** (LLM 미사용·무료) → `/api/weekly/collect`, 풀 현황 표시.
  - **② 주간 큐레이션 + 하이라이트** (기간/Top-N 지정) → `/api/weekly/curate`.
  - **⭐ S&I Weekly Highlights** 편집 패널: contenteditable headline/reason, 순서 이동, 제외.
  - **카테고리 카드**(5개): 기사별 **S&I Insight**(=`ai_comment`) 편집.
  - **뉴스레터 HTML 미리보기/복사**.
- `getOverrides()` 가 index.html과 동일 스키마 + `enabled_categories` 전송. `postAndPoll()` 로 `/api/weekly/*` 호출 후 job 폴링.

## 5. 최근 완료 작업 (직전 세션들)

1. **한줄평/한줄요약 잘림 수정** — AI가 30자 초과 문장을 쓰면 단순 절단돼 "…리스크에 / …전환 없이"처럼 미완결로 끝나던 문제. ① 프롬프트가 처음부터 30자 완결로 쓰게 + 명사형 마무리 허용, ② `_clamp_insight` 완결-인지형 재작성(매달린 조사·연결어미 제거)으로 해결. 웹·엑셀 동일 데이터원이라 동시 해결.
2. **편집 가능한 프롬프트 지침** — ①안전방식. 구조는 고정, 공통+카테고리별 지침만 웹에서 편집 → 재배포 없이 적용. (광고성 기사 제외 같은 카테고리 고유 규칙 가능.)
3. **공신력 가중 선정** — `AUTHORITY_RANK_WEIGHT` 로 동점/근소차 시 공신력 우선.
4. **하이브리드 Weekly 전체 구축** — 백엔드(collect/weekly 모드, 2단 선별, 하이라이트), app.py 3개 라우트, weekly.html UI, index.html GNB 버튼.

## 8. 배포 방법

4개 파일을 GitHub 저장소에 올리면 됨.
- **프론트(GitHub Pages)**: `index.html`, `weekly.html` — 같은 폴더에 두면 GNB 버튼이 `weekly.html` 로 이동.
- **백엔드(Render)**: `app.py`, `collect_news.py` — Render가 자동 재배포. (단, 위 "오버라이드 통로"로 들어가는 설정 변경은 재배포 불필요.)

## 9. 환경/작업 메모

- 셸은 `/bin/sh` (process substitution `<(...)` 불가 → 임시파일 사용).
- 검증: Python `python -c "import ast; ast.parse(open(f).read())"`. JS는 `<script>` 본문 추출 후 `node --check tmp.js`.
- Render Free 타임아웃 900s → 긴 작업은 백그라운드 스레드 + 폴링.
- 엑셀과 웹은 **동일 데이터원**(`ai_comment`/`ai_short_summary`) → 생성 단계(collect_news.py)만 고치면 양쪽 동시 반영.

## 10. 대화/페르소나 지침 (사용자 선호)

- **항상 한국어**로 응답.
- 톤: 컨설턴트/멘토/어드바이저. AI라는 언급 금지. 사과·후회·면책(disclaimer) 표현 금지.
- 복잡한 작업은 단계로 쪼개 근거와 함께 설명. 다관점·대안 제시. 모호하면 먼저 확인 질문.
- 코드 작업 시 **이미 만들어진 것을 재확인**하고(이 문서 + 첨부 파일), 중복 재구축하지 말 것. 기존 구조(오버라이드 통로·고정 프롬프트 구조·완결 클램프)를 유지하며 확장.
